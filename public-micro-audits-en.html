Public Micro Audit Examples

These examples use public pages and public repository information only. They are not client case studies. They show how I turn surface-level design feedback into conversion, trust, and next-step fixes.

Virling

Public page: virling.com · Topic: revenue attribution

  1. Separate the free self-hosting path from the hosted waitlist so users do not think the product is unavailable.
  2. Move the persuasive revenue-per-visitor comparison closer to the first screen.
  3. Repeat read-only key and data-boundary reassurance near the $19 hosted price.

Papertrail

Public page: subtrace.app · Topic: automated receipt collection

  1. Repeat read-only OAuth, encryption, and no-delete permissions near “Start filing free”.
  2. Make the Free plan’s source or volume limits visible before signup.
  3. Label automated examples as sample data to avoid implied performance claims.

Menivor

Public page: menivor.com · Topic: TikTok-ready demo videos

  1. Split App Store users from “any link” users into separate entry paths.
  2. Turn the free and card-verification steps into one simple timeline.
  3. Place the three most relevant showcase examples near the first CTA.

Megaphone

Public page: Megaphone · Topic: launch readiness

  1. Show a static sample report before asking for a GitHub repo.
  2. Separate English global channels from Chinese community channels.
  3. Clarify which public repo data is read in-browser near the privacy claim.

Worksitem

Public page: worksitem.com · Topic: construction cost estimates

  1. Create separate paths for homeowners and contractors.
  2. Show a sample itemized PDF so users know what they will receive.
  3. Unify tool-count wording across the site and GitHub repository.
